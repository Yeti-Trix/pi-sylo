## [Unreleased]

### Added

- **Image studio (sylo-image-gen) — local image generation, agent tools, Images route, workspace image library:**
  new optional package that adds all-local image generation through the operator's own **ComfyUI** install
  (HTTP only — never bundled, never spawned, no cloud providers, no provider keys, no Python of its own).
  Five agent tools (`sylo_image_gen_generate` / `_list` / `_get` / `_organize` / `_doctor`) drive a
  draft→final loop — fast low-res drafts (Z-Image Turbo; seconds) then a committed final
  (Qwen-Image 2; minutes) with `parent_id` lineage — both Apache-2.0 by default, with FLUX dev models as
  non-commercial-badged opt-ins. Generations save into a per-workspace image library
  (`<workspace>/.sylo/images/`: JSON index + dated pixel files, atomic writes,
  prompt/tag/favorite/model/date queries, draft/final auto-tagging) shared by chat inline results
  ("Generated images" class — no
  misleading untrusted-web footnote; full-res via `sylo-file://`, preview under the telemetry cap) and a
  new **Images** sidebar route (Generate composer with draft/final control + job card + result strip,
  Library grid with search/favorites/filters and a cost/time ledger footer, detail drawer with full
  params + Remix/Rerun-as-final, Settings with ComfyUI health + guided model install + preset defaults).
  Enable in Capability manager → **Image studio**; agent and host share one store and one ComfyUI client.
  Package-level itemization: `packages/sylo-image-gen/CHANGELOG.md`.

- **Video studio (sylo-video-gen) — local video generation, agent tools, Videos route, workspace video
  library + durable render ledger:** new optional package that adds all-local video generation through
  the operator's own **ComfyUI** install (the sylo-image-gen twin — HTTP only, never bundled, never
  spawned, no cloud providers, no provider keys). Three v1 modes ship as preset graphs on Apache-2.0
  Comfy-Org Wan repacks: **clip** — text→video / image→video ~5 s, fast drafts on Wan 2.2 ti2v 5B
  (720p@24) then committed finals on Wan 2.2 A14B (fp8 two-stage high/low-noise sampling with the
  lightx2v 4-step LoRAs, ≈1–2 min/clip est. on a 5090); **living-photo loops** — one still animated by
  `WanFirstLastFrameToVideo` with the SAME image at first+last position (cinemagraphs as song
  backdrops; pixel-exact in-graph trim of the duplicated final frame; optional native frame
  interpolation, off until the pack is installed); and basic **video→video restyle** — Wan 2.1 VACE 14B
  with a strength knob (masks/object replacement stay v2). Five agent tools (`sylo_video_gen_generate`
  / `_list` / `_get` / `_organize` / `_doctor`) carry the same draft→final economics and discipline as
  Images — library-first checks, free-VRAM + queue preflight with doctor-guided download pointers,
  count capped at 1–2 — and the signature crossover: `from_image_id` animates a still born in Images
  (read-only one-way lineage, soft-fails when Images is absent, never a back-write). Deliberate
  divergence: renders persist in a durable `jobs.json` ledger, so minutes-long clips survive a relaunch
  and recover via a read-only ComfyUI history replay (GETs only — never resubmits); every graph also
  saves an in-graph first-frame poster (no ffmpeg anywhere in v1). Clips + posters save into a
  per-workspace video library (`<workspace>/.sylo/videos/`, atomic writes, corrupt-index recovery,
  prompt/tag/favorite/mode/date queries with a GPU-time ledger footer); chat results render as poster
  previews under a "Generated videos" heading (never a multi-MB inline video); and a new **Videos**
  sidebar route (Generate composer with mode/preset controls + job card, Library grid with search and
  filters, detail drawer with native player + lineage/remix, Settings with ComfyUI health + guided
  model install + preset defaults) docks to the canvas through the generic skill-route machinery —
  `sylo-file://` gained `.mp4`/`.webm`/`.mov` for route playback. License discipline matches Images:
  Apache-2.0 Wan entries commercial-ok; `ltx-2.5`/`hunyuanvideo-1.5` are present-but-unwired badged
  opt-ins; MiniMax-H3 / CogVideoX / Sora are excluded from the catalog entirely. Enable in Capability
  manager → **Video studio**; agent and host share one store and one ComfyUI client. Relaunch Sylo to
  pick up the wiring (main/preload/renderer). Package-level itemization:
  `packages/sylo-video-gen/CHANGELOG.md`.

- **Sidebar: pin chats (right-click → Pin) — pinned chats never auto-archive, stay on top, and drag-reorder:** every chat row's context menu now leads with **Pin / Unpin**. A pinned chat sorts above the unpinned chats in its workspace section (pin glyph on the row) and keeps that spot no matter what else was touched recently; the retention sweep exempts pinned chats entirely (no auto-archive past the window, no auto-delete when empty), while manual Archive still works (unarchive puts the chat right back on top with its pin intact). Pinned rows also drag-reorder among themselves — grab a pinned row and drop it between other pinned rows (accent drop-line shows the insertion edge, same HTML5 pattern as the workspace sections); the new order persists per workspace in `pin_rank` and survives restarts. Guardrails: reordering is suspended while the sidebar search filter is active (ranks computed from a filtered subset would be wrong), dropping outside a pinned row/section does nothing, a cross-workspace drop is ignored, and "New chat" no longer cannibalizes an operator-pinned empty chat as its reuse target. Storage: two nullable columns on `conversations` (`pinned_at`, `pin_rank`) + `conversations:setPinned` / `conversations:reorderPinned` IPC through the usual preload surface. Relaunch Sylo to pick up (main-process change); the migration is two nullable `ALTER TABLE` columns on existing DBs, no data touched.

- **Expanded subagent pills replay the run's working trace (tool pills + reasoning pills, like the main chat):** the subagent child now records a bounded think/text/tool sequence per run — each tool call as `name + arg preview + duration (+ error mark and result tail when it fails)`, the reasoning and assistant text that led into each call as collapsible reasoning pills and short text paragraphs — persisted on the run row (spec) and replayed as a **Working trace** section in the detail drawer, inline pills AND Tasks/board detail: the drawer body now reads like the main chat's working stream — recorded pills first, then the live reasoning pill as a COLLAPSED one-liner (◆ Reasoning… · live, click to open) at the end of the flow instead of the old auto-expanded thinking wall pinned above everything. Updates ride the existing coalesced `subagent_run_update` stream and only carry the array when it changed; the final trace rides `subagent_run_end` so finished runs replay in full. Runs dispatched before this change keep the previous single last-tool line. Also: expanded pills now open on the working step immediately instead of an empty box (single-run batches rendered nothing; parallel/chain needed a second click).

- **Agent panel replays the run's working trace too (operator: “show the trace from chat in the agents panel”):** expanding a run row in the Agent canvas panel (the `+` picker's Agent board) now shows the same bounded think/text/tool pill feed the chat pill replays — tool pills with arg preview + duration + error marks, collapsible Reasoning pills, short text lines — under a **Working trace** heading (marked “— live” while the run streams; the board's debounced workspace snapshot now carries the trace tail on every row so it updates while working). The lone ⚙ last-tool line stays only as a fallback for runs recorded before the trace feed, and finished-run rows keep their result in chat (“open in chat →”). Shared `TracePill` component extracted so the chat drawer and the panel render the identical feed; board rows cap the trace at the last 80 entries (same cap as the run row itself). Covered by a new case in `npm run test:subagent-board` (bounded tail; empty-array fallback for old/bad specs).

- **Freeze diagnostics in Developer → Testing — what was actually loading when the app stalls:** for the two reported freezes (work machine: chat switching freezing the app; pasting pictures/files then pressing Enter hanging before anything shows), the Testing tab is now organized into sections via a sub-tab strip — **Freeze diagnostics** and **Eval dashboard** (new sections slot in beside them) — and the freeze card gets: It shows the main process's own perf ring buffer (`perf:recent`) so after reproducing a stall you can see exactly which stage ate the time instead of guessing "chat or a running turn": `chat.load` (the sync SQLite read + payload the renderer gets on every chat switch, with row count and KB), `chat.focusSession` (the full Pi session rebind that runs when you click a chat whose agent session isn't loaded yet — that's the "something is loading" on switch; renders stay free), `chat.sendPrepare` (the SYNC image encode inside `chat:send` that blocks the whole app per image), `image.encode` (per-image phase breakdown: read+decode / resize+JPEG / base64), `chat.sendBroker` (broker slot wait) and the two synthetic probes — **"Probe: heaviest chat timelines"** (per-conversation row count / payload KB / real `listMessages` ms via a cheap SQL aggregate, no bodies loaded) and **"Probe: image-encode cost"** (a noisy synthetic ~2500×1400 screenshot pushed through the exact encode pipeline, reporting each phase) — plus Refresh/Copy-report buttons. Backed by a new main-process `perf-log.ts` ring buffer (console `[perf]` lines + `perf:probeConversationLoad` / `perf:probeImageEncode` IPC through a new `perf` preload namespace) and covered by `npm run test:perf-log`.

### Fixed

- **Companion plugin tabs (Nutrition/Workout/Vitals) are not blank anymore — `personal_app_not_built` race (operator report 2026-10-14):** the companion server snapshots the plugin static-app roots ONCE at server start, but host plugins (sylo-health) register their `/personal-app/<id>` root through an async dynamic import that can land AFTER that snapshot. When the plugin loses that boot race the handler kept an empty roots map the whole session: every plugin-tab iframe then got 404 `personal_app_not_built` (a blank page) — chat + system still rendered because they live in the main shell — while the manifest endpoint kept working (it reads the loaded plugin live), so the tabs stayed in the bar but showed nothing. The `/personal-app/*` routing branch now reads the roots map live per request (the manager passes an accessor, not a snapshot), so a late registration serves immediately with no restart required; also drops the dead `legacyPersonalAppRoot` var. Verified via the live server (404 before) and a path simulation against the real on-disk health app (index + assets return 200 through every appBase shape).

- **Local tool-result media links open in the OS default app instead of dying silent (found live 2026-10-13):** generated images in chat carry `sylo-file://preview?path=<abs>` hrefs, which `isExternalLink` (http/https/mailto only) never matched — so `setWindowOpenHandler` returned `{action:'deny'}` for "click to open the source" and **absolutely nothing happened**. The handler now extracts the local path (`sylo-file:` `path` query param + plain `file:///`) and routes it to `shell.openPath` — the operator's default photo app (Windows Photos) opens the actual file; unknown schemes still hard-deny exactly as before.

- **A ComfyUI port flip no longer bricks image/video generation ("ComfyUI not reachable … even though comfyui is running", found live 2026-10-13):** the operator restarted ComfyUI Desktop and the engine bound :8189 while both sylo configs pinned `http://127.0.0.1:8188` — every tool call refused with ECONNREFUSED, doctor printed NOT REACHABLE, generate blocked. Both clients (sylo-image-gen + sylo-video-gen) now resolve the endpoint first (`resolveComfyEndpoint`): the configured URL wins when it answers; when the configured LOOPBACK port refuses and the sibling known port (8188/8189) answers, the sibling is used (uploads, object_info probe, submit all talk to the SAME resolved url) with a one-line chat notice; when nothing answers the ORIGINAL url is returned so tool error text still names it and the rich recovery guidance survives. Doctors print `engine answered on a FALLBACK probe (…)` + an update-hint so the config mismatch is visible; live configs were flipped to :8189 in the meantime. Covered by dedicated resolveComfyEndpoint tests in both clients (down-fallback / up-wins / dead-returns-original / custom-URLs-never-probed).

- **The Videos dashboard now shows renders in flight — "In progress" cards with elapsed time, ETA and a % bar (found live 2026-10-13):** the ledger already tracked queued/running rows but the Videos route surfaced nothing until the multi-minute render returned. The Library screen gained a ledger-polled strip (5 s, zero RPC when idle — the poller also powers a completion fan so the grid refetches by itself the moment a job lands): per job it shows In progress/Queued, mode+model+frames, live-ticked elapsed, an ms-per-frame ETA from same-model library history (first render of a model honestly shows "estimating from first render…"), a % of the estimate capped at 96 (never claims done before bytes are on disk), a thin progress bar, and the prompt. `(packages/sylo-video-gen/ui/src/screens/JobProgress.tsx, wired into LibraryScreen; styled in styles.css §5.6b)`

- **Video studio detects installed Wan models again — the weights gate + doctor stopped lying to real ComfyUI:**
  `fileNamesIn()` read the node schema as `{ class: { inputs: { key: [choices] } } }` — real ComfyUI /object_info
  (verified against a live 0.39.2 build) nests it as `{ class: { input: { required: { key: [[…choices], {tooltip?}] } } } }`,
  so `comfyModelsDetected` answered `false` for EVERY model on ANY live server: `sylo_video_gen_generate` refused
  to submit even with every file on disk (the doctor-guided “download the listed files” loop) and the doctor printed
  all models as MISSING forever. The parser now reads the real shape (input.required + input.optional, unwrapping
  `[choices, opts]`, deduping across containers) and still tolerates the legacy `{ inputs: { key: […] } }` layout so
  older installs keep detecting. Test fixtures stopped mocking the wrong API: the `comfyModelsDetected` suite pins
  the real shape (tooltip-wrapped choices + the missing-leg case) plus a legacy tolerance case; `test:client` 27 ✓,
  and a live re-check against a real server returns ti2v-5b/a14b true with vace (not installed) correctly false.

- **The Agent panel is now GLOBAL — and no longer blank or lying (operator reports 2026-10-11/12):** the canvas "Agent" dashboard was per-workspace and rendered NOTHING when its workspace had only finished runs (video-gen's lone worker died seconds after dispatch, the orphan sweep finalized it `orphaned`, the board's running/awaiting/paused sections went empty and a manual Agent tab froze at black), while the chat's pill and composer strip kept claiming "1 subagent running" forever. Now: the board is one GLOBAL panel — agents/subagents from EVERY workspace (runs join agent_tasks unscoped; the 30-newest-conversations cap that silently dropped older chats' runs is gone; chat presence lists streaming chats across workspaces with a workspace tag) — plus a **Finished — full result in chat** `<details>` section (newest 8 finished/failed/cancelled/orphaned rows, collapsed by DEFAULT per operator request; uncontrolled so live 300ms pushes never snap the operator's toggle; expanding a lost row replays its frozen working trace). The stale-pill lie is closed separately: the host-side orphan finalize now pings `subagents:lifecycle` (the channel the pill/strip read agent_tasks on) so both self-correct to the final row. The agent-facing `sylo_runs_list` RPC stays workspace-scoped (its contract is "this workspace's own work"). Suites: `test:subagent-board` row cases; new `workspace-wide run listing` case in `test:subagent-tasks-db` covers both scoping queries (run under the ABI-matched Electron runtime).

- **Background-subagent results that exceed the wake cap now point at their durable copy instead of dying mid-sentence:** a finished background run over the wake-prompt cap (planner runs routinely produce 40–60 KB plans; the old silent hard cap was 24 KB) used to arrive in the orchestrator's prompt and the stored timeline card cut at the byte with a bare `(text truncated)` — and the truncation was baked into the stored transcript, so nothing told anyone the full text survived (it did: `agent_tasks.result_json` +, for planner runs, the chat's plan file). Now the cap defaults to 48 KB and is pref-adjustable (`sylo.background_delivery_text_cap`, min clamp 1 KB); when a wake/card body is cut, the truncation marker names the durable copies (runs-board Details for the run = `agent_tasks.result_json`, and for a succeeded planner run the plan file `.sylo/plans/<conversation id>.md`); and a planner wake carries a `Plan file: …` pointer even when NOT cut, so section dispatch reads the durable file instead of a re-typed digest. The wake prompt tells the orchestrator to follow the pointer and act on the full text.

- **A subagent child that dies mid-turn no longer leaves a ghost "running" row:** the stall watchdog (5 min cloud / 10 min local + finalize grace) and the broker-exit sweep already covered hung children and full-broker death, but the failure shapes actually hit this session — a child dying in a way that never emits `subagent_run_end`, and a notify:"all" batch whose sibling never reports — had no terminal path: the row stayed `running` forever, `subagentsRunning()` stayed true (blocking plan cleanup by design), the runs board showed a live ghost, and the chat was never told a completion was never coming. Three closes: (1) a host-side **orphan reconcile sweep** (60s tick, pref-adjustable `sylo.orphan_reconcile_stale_minutes`, default 15 min — deliberately ABOVE the watchdog + grace so the watchdog's informative `failed` verdict always lands first): every broker lifecycle event bumps the row's `updated_at`, so a `running` row quiet past the window is finalized `orphaned` (`child_died_no_run_end`) and the owning chat gets the lost-run card the broker-exit path already posts (headline "A background subagent died without reporting a result"); (2) **`subagentsRunning()` is zombie-aware** — it counts only rows seen alive within the quiet window, so a stuck row can no longer block plan clearing forever; (3) **notify:"all" groups escape a dead sibling** — 10 minutes after the last held completion with no live sibling left in the run registry, the held completions flush to the dispatching chat instead of sitting forever. Covered by the new `npm run test:subagent-tasks-db` suite (runs under an ABI-matched runtime — verified passing under electron's Node; self-skips under plain node here because better-sqlite3 is Electron-ABI in this checkout).

- **Planner output is cleaned before it becomes the chat's plan file:** the planner's entire final message used to be saved verbatim, so conversational preambles (which sometimes guessed a wrong save path), closing summaries, and a ` `` `-fenced plan embedding its own `topic:` frontmatter landed on disk. New `planBodyFromPlannerResult()` (plan-file.ts) unwraps a goal-bearing fence (only when the `## [ ]` goals live inside it — a fenced code sample in the preamble cannot become the plan body), strips the embedded frontmatter, cuts the preamble at the plan's first non-fenced heading, and drops a trailing `Plan saved to …` / `Saved to …` epilogue under any phrasing. `planner.md` now also instructs the persona to emit only the plan (no preamble/summary/fence, never state a save path). Covered by 4 new cases in `npm run test:subagent-plan-file`.

- **`sylo_chat_export` with a relative `out_path` resolved against the host process cwd and failed ENOENT:** it neither mapped the path onto the chat's `ctx.cwd` nor created the target's parent directory. Relative `out_path`s now resolve against the chat cwd and the parent dir is created (`mkdir -p` semantics), matching what the default `journal/` paths already did; the manifest no longer claims a custom path lives under `journal/`.

- **Canvas resize no longer stops way early on wide monitors:** the docked canvas is whatever's left over after the chat pane, and the chat pane was clamped to a hard 960px — so the canvas could never shrink below `windowWidth − 960`. On a ~2543px window that pinned the canvas at ~1345px (over half the screen) no matter how far the handle was dragged. The chat-pane ceiling is now window-aware: it grows with the window (minus the sidebar) so the canvas can be dragged down to max(140px, ~10% of the viewport). Stored pane widths ≥ 960 from a dragged session now survive a restart instead of being clamped back to 960 on load. Covered by new cases in `npm run test:canvas-layout`.

- **Clicking a running subagent pill now shows its live working trace immediately (was an empty box):** expanding the “Subagent · planner · RUNNING” pill rendered nothing for single-run batches — the forced `@planner` / `@orchestrator` / background dispatch shape — because the run-row list only renders for parallel/chain batches and the detail drawer only rendered for a row the operator explicitly clicked; there was no row to click. The pill now falls back to the batch's focus task as soon as it expands (same rule the Tasks board uses): while working that's the newest running step's live trace — streaming output preview, live reasoning block, and last tool call, updating via the run's lifecycle events; on a finished batch it opens on the step that best explains the batch (failure first, else the final step's output). Parallel/chain pills get the same treatment (no second click needed to see anything), row highlights and the chain stepper follow the effective selection, and clicking a specific row still pins it — clicking it again returns to following the live step.

- **Pasting a picture then pressing Enter no longer stalls the app before anything appears in chat:** the operator saw a delay “like it's analyzing them before showing them in the chat.” Two causes, both addressed. (1) Composer paste used to add its attachment chip only AFTER the image was persisted host-side (a `writePastedImage` round-trip) — big screenshots or phone photos looked like the paste silently did nothing; paste now mirrors the existing drop path: a pending “reading…” chip appears instantly and upgrades in place when the real path resolves. (2) `startChatTurn` + `followUpActiveTurn` used to insert the persisted user message row only after the synchronous image encode (seconds for large images, and it blocks the Electron main process — the whole app, all windows — for that span); the user row is now inserted **before** the encode so the message is in the chat (the composer's optimistic bubble already covered the first frames) and the encode-produced delivery-metadata block is patched into the same row right after, ending in the identical persisted shape as before. Image resize when re-encoding oversized screenshots also drops from resize quality `best` to `good` (the output is a ≤1568px vision payload, not a display asset), cutting the main-process block on big images multiple×.

### Added

- **Chat timeline: the Working pill now renders under the upload/page-preview pictures:** while a turn is on an operator upload (the "PDF page preview" cards and tool-result pictures), the picture cards used to render BELOW the "Working… · N tools" pill at the top of the work run; now they LEAD the run, so the rendered pages stack on top and the working pill sits underneath — reading previews first, then the live trace. Split the work-run `galleries` bucket in `ConversationMessage.tsx`: upload/document picture galleries go to a new `media` bucket rendered above the run pill (live and completed runs share this order, so nothing jumps when the turn completes), while subagent run pills keep their committed external below-the-pill placement untouched. (pi-sylo-dev #30)

- **Inactive-chat retention is now operator-configurable — enable/disable checkbox + window length:** the startup sweep that archives chats with no activity (previously hard-coded to 30 days) is now controlled under **Settings → General → Inactive chats**. A checkbox ("Automatically archive inactive chats at startup", on by default, so existing behavior is unchanged) gates the whole sweep, and a "Days before archiving" number input (default 30, bounds 1–3650, blank/garbage snaps back to the last valid value) sets the window; both persist as prefs (`sylo.retention.auto_archive`, `sylo.retention.days`) through a new shared module `apps/host/src/shared/sylo-chat-retention-settings.ts` agreed on by main and renderer, with clamp/normalize helpers covered by the new `npm run test:chat-retention` suite. What the sweep does is unchanged: inactive chats with messages are archived (kept in full, restorable from the sidebar's Archived section) while empty chats are still hard-deleted; with the switch off, nothing is archived or deleted at startup. The resolved window now also feeds the two adjacent startup housekeeping prunes (stale subagent host sessions, stale web-access runs) so one number governs retention — those prunes are not gated by the switch, since they are internal bookkeeping rather than chats.

- **One workspace agent window — the Subagents board now spans every chat (F1/F2):** the canvas “Subagents — Runs” board used to show only the dispatching chat's runs (a later chat's first background run took the board over), so work running in another chat was invisible until its completion message landed. The board is now **per workspace, listing every subagent run from every chat** — each row shows the persona, the task headline (first line of the dispatch), its **owning chat** (name; rows also carry the chat id), model (shown from dispatch time now — B4), touched files, tokens/elapsed, and its live output tail; the current chat keeps its pinned in-chat runs block unchanged. Above the runs sits a **presence section** — every non-archived chat in the workspace with a live/idle dot: what that chat's agent is working on right now (latest assignment line) when a turn is running, otherwise when it was last active. Rows are clickable to open the run's full report (reasoning, output, usage, cancel/retry) in an overlay, and finished rows + every running run can be jumped to the owning chat; cancel runs through the same guarded path as before. Agents get the same picture with a new **`sylo_runs_list`** tool (host RPC in the think-tank pattern): before dispatching a subagent or editing files, the orchestrator in ANY chat can now see which other chats are live, what they are working on, and the files their runs touch — one cheap query instead of the multi-session file collisions these sessions kept hitting. Chain completions now also carry a stable group id so the host can attribute delivery even when no per-step row matches.

### Added

- **"Compaction in progress" banner in chat:** a compaction status card now appears in the conversation the instant compaction starts — manual "Compact now", the auto threshold trigger, and context-overflow recovery all write a persistent amber "Context compaction in progress" banner (pulsing dot, so it's obvious from a glance) before Pi begins summarizing. It lives in the chat history itself, so leaving for another chat and coming back shows the truth: still running (banner live), compacted (token before → after + summary button), cancelled, or failed — updated in place on the same card, never a duplicate. Previously the only trace was the result card after everything finished, so a compaction left running looked like it had never started. Interrupted compactions settle as "cancelled" via the turn's cleanup, and banners that outlive a crash are swept to "cancelled" on next launch.

- **Turn timer pauses while an agent waits on your answer:** the live "Turn ·" / reply elapsed timers now count agent run time, not wall-clock — when a turn parks on an ask-question, the timer freezes at the pause start (and stops pulsing, with a "paused — waiting for your answer" tooltip), and when you answer (here or from the companion) it resumes from the frozen value because every paused interval is subtracted. Multiple questions in one turn bank separate waits; a turn boundary resets the accounting so the next turn counts from zero. The host stamps each question's open time, so even a desktop reload mid-wait re-anchors the pause correctly.

### Added

- **Plan goals bar close button:** an ✕ at the top-right of the plan-goals bar above the composer hides that chat's plan on demand. It patches the same frontmatter `hidden` flag the finished-plan path uses — nothing is deleted, ticks and the Reviewed badge keep their meaning, and saying "continue" in that chat puts the plan back with its goals intact. ### Fixed

- **Chat/companion markdown tables no longer crush narrow label columns into vertical letter stacks ("R/a/n/k", "Atla/nta/") while prose columns soak up all the width:** in the table auto-layout algorithm Chromium treats `word-break: break-word` wrapping as always-available when computing column minimum content widths — so with `.chat-md table { width: 100% }` and long-prose cells plus message bubbles inheriting `overflow-wrap: anywhere` from ui-classes (both reduce cell min-content to ~one character), the browser's width distribution handed nearly the entire pane to the long columns and left the 1–2-character label columns (Rank, City in a city-comparison table) at 15–40px with their words broken letter by letter. Table cells in both `.chat-md` stylesheets (host renderer + companion) now use `word-break: normal; overflow-wrap: break-word`, which keeps a column's min-content at its longest word (so a label column can never shrink below it while the table still has spare width) and still emergency-breaks unbreakable tokens (a lone long URL/path chip) only when that token physically can't fit. Verified with a headless-Chromium A/B harness kept at `lab/table-width-test2.html` reproducing the exact table: Rank column 28px → 43px, City column 36px → 58px under identical content and container width; headers/cells wrap normally otherwise.

- **Speech (TTS) now self-heals on enable — unpinned transformers/scipy no longer break Kokoro:** enabling Speech left Kokoro dead with the cryptic `Kokoro import failed (Could not import module 'AlbertModel')` on every Generate because `pip install -r requirements.txt` claimed "already satisfied" while the env was broken: transformers 5.x hard-imports scipy at startup (its new loss modules) and scipy 1.18 requires numpy≥2 while Kokoro pins numpy<2, so the import chain exploded and transformers wrapped the real error into unreadable noise. The TTS requirements now pin the fragile stack (`transformers>=4.46,<5.0`, `huggingface-hub>=0.34,<1.0`, `scipy>=1.15,<1.17`) so one pip pass both installs fresh envs and repairs out-of-range versions on re-enable; the pre-Generate readiness probe became a deep import check (`from kokoro import KPipeline`, no model download) that re-verifies after pip and reports the real root-cause chain plus a force-reinstall hint instead of repeating until app restart, and a failed ensure no longer caches a permanently-rejected promise (next Generate retries). The Python synthesizer flattens exception `__cause__`/`__context__` chains when a Kokoro import fails, so agents and users see e.g. `AttributeError: module 'numpy' has no attribute 'long' <- ModuleNotFoundError: Could not import module 'AlbertModel'` instead of the transformers-only message.

- **Orpheus voices just work now — no manual pip step, and the Kokoro/Orpheus numpy conflict is gone:** picking an Orpheus voice produced `Orpheus-cpp import failed (No module named 'orpheus_cpp')` because its deps were documented as a manual, conflicting install (requirements-orpheus.txt demanded numpy≥2 while the core file pinned numpy<2). Kokoro 0.9.4 is verified to synthesize identical output on numpy 2.x, so the core pin is relaxed to `numpy>=1.26,<3`; requirements-orpheus.txt now ships `llama-cpp-python` (PyPI CPU wheels, no toolchain needed on Windows) so one pip pass installs the whole backend; the Speech capability installs it **best-effort at enable** (an Orpheus failure can never block a Kokoro-only enable), and any skipped/failing install self-heals on the first Orpheus use — a backend-aware probe `from orpheus_cpp import OrpheusCpp; import llama_cpp` runs before Generate in the host (tts-engine) and before `sylo_tts_speak` in the agent tool (python-runner), auto-installing and re-verifying, with the root cause shown only if a manual repair is truly required.

- **A question pending in one chat no longer freezes sends in every other chat:** a turn parked on an unanswered question counted as a busy slot, so outside concurrent turns mode every other chat's message queued behind it indefinitely — looking exactly like a dead send, with no explanation anywhere. Questions now hold only their own chat: while the primary broker waits for your answer, other chats' turns start on a temporary overflow broker (the same lifecycle concurrent mode already uses) and the app returns to its normal concurrency rules once you answer. Queued turns also flush as soon as the only remaining in-flight turn is question-parked.

- **Background subagent results are no longer delivered to the wrong chat (or silently dropped) — root cause of both lost completion messages and the stale “N subagents running” counter (B1/B2):** the broker child stamps every subagent lifecycle event with its *currently active* prompt's turn id. A background run's `run_end`/`run_completed` arrive minutes after its dispatch turn ended, so when the same broker child was meanwhile streaming a different prompt (another chat on the same overflow child, or a steer queued into an open turn), the stamp pointed at that foreign turn — the result card was written into the wrong conversation (the owning chat saw nothing) and the owning chat's runs strip missed the terminal refresh, keeping its last snapshot (“1 subagent running”) while the database had zero live rows. Attribution now resolves from the `agent_tasks` row first (it was created inside the dispatching turn, so its conversation is authoritative), with the group run id as a fallback for chain completions; the turn stamp remains only for `run_start` and as a last resort. Unresolved completions are logged loudly (`[subagent delivery] …`), and the workspace Subagents board stores every finished run's report on its row, so a result is readable even if the chat-card path ever throws again. The renderer's per-chat runs list also got a fetch-generation guard so a slow in-flight snapshot can no longer overwrite a newer one.

- **Unknown subagent persona no longer records a phantom “FAILED 0s” run (B3):** the extension emitted `run_start` and a failed `run_end` before checking that the requested persona existed, so dispatching a typo'd or model-named agent (“haiku” — the model, not a persona) left a junk FAILED entry in the runs panel. The persona is now resolved (and the Capability policy applied) before any lifecycle event; a refusal returns a tool result that names the mistake, lists the available personas (`Unknown agent "haiku". Available: scout, planner, worker, reviewer`) and points a repo persona's name at the Subagents modal to activate it — and no run row is recorded.

### Added

- **Companion app shows the "answer needed" state too:** the phone chat list now shows the same pulsing **?** badge + glowing chat title when an agent is paused on a question (parity with the desktop). It also survives a PWA reload and reconnects — the desktop host serves the live unanswered-question payloads on the conversations endpoint, and the phone (and a reloaded desktop) reseed their question store from it.

- **Chat list shows when an agent needs an answer:** a chat whose agent paused on a question now shows a pulsing **?** badge in the chat list instead of the running spinner, and its title gently fades and glows until you answer — visible from anywhere in the app, not just while that chat is open. The badge clears the moment you submit the answer (or when the turn ends / a new turn starts), so it never sticks on a dead turn.

- **Compact now — chat footer button:** a **Compact now** button next to the context token counter (both chat layouts) runs Pi's manual compaction on the active chat on demand — like Claude's `/compact`. It summarizes older turns into a compact note and frees context space immediately; the same compaction-notice card as auto-compaction appears in the timeline (labeled "manual"), and the footer token count drops. Disabled while the chat's turn is streaming (the host re-checks too, so a stale click can never abort an in-flight turn), with inline errors for "nothing to compact", "already compacted", or a busy broker.

- **Per-model compaction trigger — choose when context is summarized:** Settings ▸ Model (Pi) now has a **Compaction** section. Pi's default (compact when the context window fills to `window − 16,384` reserved tokens, ≈91.8% on a 200k model) is shown for the selected model, and you can override the trigger as a % of that model's context window. Overrides are stored per model (switching models and back keeps each model's trigger), a **Restore default** button returns to Pi's built-in behavior, and saves apply to live sessions immediately — no broker restart. Host→broker plumbing carries the resolved reserve on every session init/switch, so each conversation's model always gets its own trigger.

- **Manage providers — configure every provider from one place:** Settings ▸ Model (Pi) ▸ **Manage providers** opens a modal listing all six providers (Ollama, ChatGPT OAuth, OpenAI, Anthropic, Groq, OpenRouter) with live status — key saved + masked preview, ChatGPT sign-in state, Ollama reachability — and inline actions to save/replace/remove API keys or sign in/out, all independent of the active chat model. Saving refreshes the chat and subagent model pickers immediately, and a broker-restart shortcut applies new credentials to live sessions.

- **Docs — free models for low-stakes subagent work:** guidance in docs/GETTING_STARTED.md + AGENTS.md on pinning a free model (e.g. Nemotron 3 Ultra on OpenRouter) to scout by agent name so high-volume, low-intelligence subagent tasks (websearch, doc reading, recon) run free instead of burning paid tokens.

- **Queued follow-ups — inline edit:** every queued message chip now has an ✎ edit action. Enter saves, Shift+Enter adds a line, Esc cancels. The attachment paths attached to the queued message are preserved verbatim while you edit the prose; emptying the text removes the item (unless it carries attachments).

- **Chat concurrency — configurable max in-flight turns:** the "Allow concurrent agent turns across conversations" setting now lets you pick how many turns may run at once (1–16, default 4) instead of a hardcoded 4. New "Max concurrent turns" number field in Settings ▸ Chat concurrency; each in-flight turn beyond the first still uses its own Pi broker process.

- **Schedules — per-schedule chat mode:** every schedule can now choose between **"New chat each run"** (previous, still the default) and **"Continue in same chat"** — each fire appends the prompt turn into one persistent conversation. Selectable in the Schedules form for both new and existing schedules. Self-healing: if the target chat is missing (first run), deleted, or archived, the next fire creates a fresh chat and continues there. "Run now" and startup-catchup follow the same rule.

### Changed

- **Queued follow-ups survive chat switches:** the queue strip is now remembered per conversation (in-memory, same lifetime as composer drafts). Queue a message in one chat, switch to another (or to a non-chat tab), come back — the queued message is still there instead of silently disappearing. It still auto-sends when its turn finishes while you watch that chat; if you were elsewhere when the turn finished, it waits for you (Send-now ✦ or the next finished turn) rather than firing unannounced.

- **Drop files anywhere in the chat transcript:** the whole chat area now accepts file drops and hands them to the composer. Previously only the small composer box accepted drops — anywhere else silently did nothing (the shell-level drop handler relied on `File.path`, which Electron 32+ removed).

### Fixed

- **Side chat (canvas ▸ Apps ▸ Side chat) no longer fails silently:** the send flow had five silent no-op paths — including a `sending` flag that was never reset when the parent chat changed, `createSide` failures that vanished, and ignored "deferred" turns (with concurrent turns off — the default — a side-chat send while the main chat is mid-turn is queued behind it, which looked exactly like a dead send). Every failure now shows an inline status line in the pane; a deferred send shows "Queued — it starts when the current turn in another chat finishes"; a failed send restores the typed text and resets the composer. Host side: a 5 s sweep now retries deferred turns while a broker slot is free, so a queued turn can no longer sit stuck forever if the event-driven flush loses a race.

- **Dropped files are visible immediately:** dropped files/images now show placeholder chips the instant they land ("reading…" while each file resolves), instead of appearing only after per-file processing. And a sent message with attachments now appears in the timeline right away — an optimistic user bubble renders from the moment you press Send and is replaced by the real message when the host finishes preparing the turn (image encode + broker start used to leave seconds where the just-sent files were visible nowhere).

### Fixed

- **Expanding a workspace section in the sidebar no longer switches folders (peek mode):** the workspace headers double as drag-to-reorder handles, and merely EXPANDING another workspace's section used to switch the whole app to that project folder and open its most recent chat — so a failed drag (mouse released under the drag threshold, which Chromium reports as a toggle-click) could jump you into a different folder with a chat you never chose. Expansion now only opens the section (Cursor-style peek: its chats are listed, lazily fetched) and switching happens on a deliberate gesture inside it — clicking one of its chats, or its + button. The sidebar search still focuses the active workspace (peeked sections collapse while searching).

- **A background conversation refresh can no longer adopt the wrong chat after a workspace switch:** an in-flight sidebar refresh for the OLD workspace resolving after a switch painted its list and then fell through to the saved/first conversation — yanking the active chat to whatever the previous workspace's pointer said (the same "jumped me somewhere else" shape). Sidebar refreshes now carry a generation token; stale runs discard their result instead of painting or re-selecting.
